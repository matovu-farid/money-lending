## Decisions and data contract

- Canonical URL: `/reports/weekly-payments?week=YYYY-MM-DD` and `/reports/weekly-loans?week=YYYY-MM-DD`, where `week` is the Monday date. Missing week defaults to the current Kampala week. Invalid, non-Monday, or impossible dates show an inline validation message; do not silently query a different week.
- `week=2026-09-21` represents Kampala local `[2026-09-21 00:00, 2026-09-28 00:00)`, equivalent to UTC `[2026-09-20T21:00:00Z, 2026-09-27T21:00:00Z)`. Query with `gte(column, startUtc)` and `lt(column, endUtc)`, never an inclusive end.
- Payments: join payments → loans → customers; `payments.deletedAt IS NULL`, `payments.markedWrong = false`, `loans.deletedAt IS NULL`; date field `payments.paymentDate`. Count rows and sum `payments.amount` with `BigNumber`. Include customer, loan reference, Kampala payment date/time, amount, deposit location. No creditor field.
- Loans: join loans → customers; `loans.deletedAt IS NULL`, `loans.status <> 'pending'`; date field `loans.startDate`. Include active and historical issued loans, including rollover loans, because the report is issuance history rather than current outstanding portfolio. Count rows and sum `loans.principalAmount` with `BigNumber`. Include customer, loan reference, Kampala issuance date, status, principal. If business semantics require disbursed loans only, revise this rule before implementation.
- Both cards are available to users with `reports:read` and the corresponding `payment:read` or `loan:read` permission. `withAction` accepts one permission: set it to `reports:read`, then use its **classic `action` callback** to `await checkPermission(session, "payment:read" | "loan:read")` before `Effect.runPromise(service(...))`; return `{ error: "Forbidden" }` when denied. The callback must return `{ data }` on success to preserve the existing action contract. UI gating alone is insufficient. No new Electric shape is required; do not fetch broad payment or loan tables in the browser.
- Keep monetary values as decimal strings through service, action, and collection; format only in UI. Return an empty `{ count: 0, total: "0.00", rows: [] }` result for valid weeks with no rows. Use explicit loading and error states; stale week data must not appear under a new week heading.
- **Database safety gate:** Current `cypress.config.ts` defaults `DATABASE_URL_TEST` to a `money_lending` database and `db:reset` deletes all application rows. The active app at port 3482 may point to that same database. Existing integration setup also truncates tables. Do not run Cypress, integration tests, `db:reset`, or a test server against either default URL. Provision a dedicated disposable PostgreSQL database (for example `money_lending_weekly_reports_test`) and verify by reading `current_database()` and `inet_server_addr()`/`inet_server_port()` that its identity differs from the active app's DB. Keep the active app untouched. Set `DATABASE_URL_TEST` **and `DATABASE_URL`** explicitly to the disposable URL for Cypress; unset or redirect `DATABASE_URL_UNPOOLED`, since `cypress.config.ts` uses it as `NEON_URL` for some tasks. Run a separate `CYPRESS=true` Next server on port 3000 so app and Cypress tasks use the same disposable DB. Make sure Electric/test transport, if needed by login or page rendering, is isolated too; do not point its writes or sync to the active database. Abort destructive tests if isolation cannot be proved. The manual browser check at 3482 remains read-only and needs no reset.
